### 5.2.4 - SaveClient

The `SaveClient` method is a critical function within the `ClientManager` form, enabling users to commit changes to client-specific data. After clients' IOSS numbers, EORI numbers, account codes, or active status are reviewed and modified, this method ensures these updates are securely stored in the `Appz` database. By leveraging a parameterized stored procedure, it maintains data integrity and provides an audit trail of changes made by "TAFIE" users, which is essential for accurate international shipping and proper client management in a warehouse environment.

#### Step-by-Step Breakdown

* SQL Query Definition:
* Defines the SQL command. This indicates the execution of a stored procedure named `[TCAR_Save_Client]`. This procedure takes six parameters: `@Client`, `@IOSS`, `@EORI`, `@AccCode`, `@Active`, and `@User`. Using a stored procedure for saving data is a robust practice, centralizing business logic on the database server and mitigating SQL injection risks.

```cs
string query = "EXECUTE [TCAR_Save_Client] @Client, @IOSS, @EORI, @AccCode, @Active, @User";
```

* Data Retrieval and Normalization from UI Controls:
    * Retrieves the selected client name from `cbClient`. It uses a ternary operator to ensure `client` is an empty string if the ComboBox text is null or empty.
    * Retrieves the IOSS number from `txbIOSS`. The null-coalescing operator (`??`) ensures that if `txbIOSS.Text` is `null`, `ioss` defaults to an empty string.
    * Similarly retrieves the EORI number from `txbEORI`, defaulting to an empty string if null.
    * Retrieves the account code from `cbAccCode`. This line handles cases where the text is empty or explicitly "None", ensuring a valid string is assigned.
    * Retrieves the boolean checked state from the `chkActive` checkbox, indicating whether the client is active or inactive.

```cs
string client = !string.IsNullOrEmpty(cbClient.Text) ? cbClient.Text : "";
```

* Database Interaction (Try-Catch Block):
    * The entire database save operation is enclosed within a `try-catch` block to handle any potential exceptions during the process.

* Establishing SQL Connection:
    * A new `SqlConnection` is instantiated using the `connectionString` (the global constant). The using statement ensures proper disposal of the connection resource.
    * The connection to the `Appz` database is opened using `conn.Open();`

```cs
using (SqlConnection conn = new SqlConnection(connectionString))
```

* Executing Stored Procedure with Parameters:
    * A `SqlCommand` object is created with the stored procedure query and the open conn. This using statement ensures the command is disposed of.
    * Each of the previously retrieved and normalized client parameters is added to the `SqlCommand` as a parameterized value. The `@User` parameter is populated by the `userName` global variable, ensuring that the user who performed the update is recorded, which is vital for auditing in a multi-user warehouse environment.
    * The command is executed. `ExecuteNonQuery` is used because the stored procedure is expected to perform an update or insert operation and does not return any rows of data.
    * The connection to the SQL database is explicitly closed after the operation is complete using `conn.Close();`

```cs
using (SqlCommand cmd = new SqlCommand(query, conn))
{
    cmd.Parameters.AddWithValue("@Client", client);
    cmd.Parameters.AddWithValue("@IOSS", ioss);
    cmd.Parameters.AddWithValue("@EORI", eori);
    cmd.Parameters.AddWithValue("@AccCode", accCode);
    cmd.Parameters.AddWithValue("@Active", active);
    cmd.Parameters.AddWithValue("@User", userName);
    cmd.ExecuteNonQuery();
}
```
